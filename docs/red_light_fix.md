# ms01 藍色貨車漏判修正（2026-09-20）

針對使用者指出的約 2–3 秒前方藍色貨車，使用既有 99 幀辨識 JSONL 回歸，
未更換辨識權重，也沒有用車號、物件 ID 或影片時間硬編碼觸發條件。

## 找到的阻塞點

1. 原規則要求信心值 >= 0.30 的紅燈連續 12 幀；原資料只有 8 幀達門檻，最長連續 2 幀。
   因此整段根本未進入越線判斷。
2. 越線方向只允許影像上方→下方。前方車輛駛離鏡頭時，底邊通常由停止線下方移至上方。
3. 要求拍到狹窄的線上區間；跳幀或遮擋會漏掉此過程。
4. 補償已確認的線又在規則裡重等 5 幀；線段縮小／換 ID、車輛中心被遮住及鏡頭位移，
   會丟失同一條線前後的軌跡。

## 修改

- 新增獨立 `signal_state.py`：逐燈的空間配對與時序證據，窗口 0.5 秒、至少 3 個不同影格，
  支持樣本 >= 0.18 且窗口內至少一筆 >= 0.30；缺失最多沿用 0.2 秒。
  同幀重複框不重複計票。同燈轉綠／轉黃立即切斷紅燈；多個穩定燈互相矛盾時回報未知。
- 預設 crossing_direction=away；可用 --crossing-direction toward 處理朝向鏡頭的配置。
  仍是影像空間代理方向，不代表已解析真實車道方向。
- 允許有連續證據的線前→線後直接跳轉，線後需至少 2 次觀測；狀態間斷超過 0.32 秒清除。
- 品質合格補償 component 不再重複等待完整穩定窗口，可採用 >=100 像素的已確認小片段。
- 以車框底邊與有限線段的重疊處取位置，避免中心 x 被遮住就整輛車忽略。
- 規則中的歷史線也使用補償層的鏡頭變換更新。換片段僅在短時間、重疊及近共線條件下交接。
- 事件附上前後紅燈樣本、停止線來源、交接 ID、參考點方式與線前影格，供人工檢查。
- 啟用規則時主流程額外輸出 *_rule_diagnostics.jsonl，標記影片顯示 REVIEW 候選提示。

辨識模型接口與補償輸出格式未變；此次有針對性地修正違規規則。

## 回歸結果

37 項測試通過，包含真實 ms01 片段及反向行駛、轉綠、長間斷、同幀重複燈框、
無紅燈及鏡頭／車輛同步位移的負例。

同一份辨識資料重算後，唯一候選是 vehicle-000001（truck），第 86 幀，3.44 秒。
這是車框底邊確認越到線後的時間，**不是車頭首次越線時間**；不應把它宣稱成精確違規發生時刻。
目前尚無前車車頭／輪胎接地點定位，以及明確號誌與車道配對，候選仍標記 review_required=true。
這一案例回歸成功不代表跨影片準確率已經驗證。
