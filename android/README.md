# Android 交通違規檢舉輔助系統

用 Android Studio 開啟本目錄，在 Android 8.0（API 26）以上手機執行 `app`。專案使用 Gradle Wrapper、JDK 17 以上與 Android SDK Platform 37。也可以在本目錄執行以下 PowerShell 指令。

```powershell
.\gradlew.bat clean assembleDebug testDebugUnitTest
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

## 從影片分析到官網填表

1. 在分析電腦開啟 `ui/手機展示模式.cmd`，它會啟動介面並沿用或啟動設定在本機的推論服務。手機和電腦連到同一個可信任的 Wi-Fi。
2. 在 App 首頁輸入展示模式列出的區網 IPv4 網址，例如 `http://192.168.1.10:8765`，點「進入影片分析與檢舉」。Android 17 以上第一次連線需允許區域網路存取。
3. 登入後選擇影片，匯入 GPS 軌跡或指定地點，選擇分析方式。在違規審查頁檢查佐證、建立檢舉單並核對縣市、車牌與地點。
4. 在第 5 步點「在手機開啟…自動填表」。App 以目前帳號讀取該案件及佐證，將審查後的欄位、截圖與影片帶入縣市官網。首次使用可在此填寫檢舉人資料，也可以先從專案的「檢舉人」入口設定。
5. 直接在官網處理驗證與最後送出。「返回案件」可回原審查流程。受理狀態以官網回覆為準，開啟或離開填表頁會保留電腦端案件。展示時也可選原有的「模擬送出」。

影片、GPS、分析結果和草稿儲存在分析電腦。檢舉人的身分證字號、電話、地址等填表資料由手機加密保存，依分析主機與登入帳號分隔。手機下載的案件附件放在 App 私有快取，離開原生填表頁時清理。首頁也可直接進入舊版的資料夾匯入和手動填表流程。

案件地點可用 GPS 軌跡檔、地圖點選或手動座標輸入。地圖沿用專案的線上圖磚，原有路名反查會將案件座標傳給 OpenStreetMap Nominatim。離線時可手動補上路名。

## 手機驗收

| 階段 | 操作 | 預期結果 |
| --- | --- | --- |
| 1．個資、案件與縣市 | 儲存測試個資後重開 App。選一個含 UTF-8 `info.txt`、照片與影片的資料夾，再試手動編輯與相簿選檔。 | 個資仍在。日期與時間分開顯示，附件有預覽。「苓雅區」會推薦高雄市，仍可手動改選。 |
| 2．選單比對 | 用「苓雅分局」與「跨越雙黃線」測試，再用自訂且無法比對的違規名稱重測。 | 兩個行政區都選到苓雅。「跨越雙黃線」對應到「不依規定駛入來車道」。未知的違規名稱會讓大類和小類同時標紅。 |
| 3．WebView | 開啟高雄填表頁、縮放桌面表單、查看「步驟紀錄」。在人工驗證階段按「重新注入本步驟」。 | 狀態停在人工驗證，紅框會重新顯示，已完成的附件不會重新上傳。 |
| 4．高雄完整流程 | 先用零附件走一次，再選 1～3 個測試附件。開啟填表頁後，讓 App 自動處理，觀察官網的附件件數。 | 附件會逐一上傳，每次確認件數增加後才處理下一檔。看到「官網驗證與送出」即可結束測試。 |
| 5．其餘縣市 | 選擇案件所在地，載入一張照片及一支短影片。在官網核對日期、車牌、行政區、道路、違規事實和附件。 | 一般表單會自動填入。縣市選擇頁會顯示超過網站附件上限時本次帶入的件數。 |

### 第 5 階段實機測試

* 屏東可測一般表單與多個附件欄。台中可測單頁式表單與同一欄多檔。看到附件檔名或縮圖後，在官網最後送出前離開即可。
* 新竹縣依序經過通訊資料、案件資料與要件檢核頁。雲林、桃園若先出現驗證，直接在官網完成，案件表單開放後 App 會續填。
* 本次查看宜蘭案件表單時，有違規事實選單，頁面未顯示共用設定中的獨立敘述欄。案件含敘述時請留意 App 的「違規敘述」提示，在官網核對。
* 嘉義市與台北市請最後測。自行在官網要求驗證信並完成驗證，回到同一個 WebView。嘉義市若顯示草稿清單，請自行選擇要使用的草稿或開始新案件。確認案件頁自動填入與帶入附件，嘉義市最多三張照片、兩支影片。
* 2026-11-23 驗證時，台東官網顯示停機維護。該市目前以本機測試頁檢查欄位與人工驗證停點，仍待官網恢復後實測。

ASP.NET 切換大類與上傳會將當時的表單資料傳給高雄官網。測試請使用測試資料。正式檢舉時，直接在官網核對資料、完成驗證並按官網的送出鍵。離開填表頁後，請依官網與確認信判斷是否受理。

資料夾附件按檔名排序，相簿附件依選取器回傳順序排列。高雄取畫面左起前三件，可先移除不需要的附件。開始填表後，App 會把選好的照片或影片直接放入官網附件欄，並觸發上傳。官網回報件數沒增加時，先查看網站訊息與附件清單，再決定是否重試。

個資設定使用 Android Keystore 與 EncryptedSharedPreferences。案件、附件進度、未比對欄位和步驟紀錄只在本次填表期間保留。離開填表頁或系統終止 App 後，需要重新啟動流程。

## 開發驗證

本機 JUnit 包含 Python 版 OptionMatcher 的 20 個測試案例、案件解析與流程狀態測試。連接 API 29 以上測試裝置後，執行 `./gradlew connectedDebugAndroidTest` 可重跑離線 WebView 測試。測試提供四個暫用附件，全程零點擊，核對前三件照片與影片的檔名、類型、內容與順序，以及 PostBack 後的紅框和官網驗證停點。

Gradle 直接將上層 `configs/` 設為 assets 來源，並將 `檢舉網站.txt` 打包為 `sites.txt`，供缺少 `start_url` 的設定查詢。版本 0.3 內含 20 個縣市 driver，金門與連江的 Email 流程屬第 6 階段。

0.4 版同時打包整個專案的 `ui/web`。建置時請保留 `ui` 與 `reporting/autoForm/android` 的相對位置。在專案根目錄以 `.venv\Scripts\python.exe reporting/autoForm/android/tools/project_fixture.py --real` 可啟動隔離的整合測試服務。啟動 Android 模擬器後在本目錄執行以下指令，測試使用合成影片與暫存帳號。

```powershell
.\gradlew.bat connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.projectTestPort=18765" "-Pandroid.testInstrumentationRunnerArguments.projectRealModel=true"
```

區域 driver 的 WebView 離線測試另涵蓋 20 個入口與設定的打包檢查、台北信箱驗證後同頁續填、嘉義市照片與影片的分組附件，以及台東表單的驗證停點。這些測試使用本機替代頁面。正式網站的收件結果、驗證信投遞與大檔案限制需由各縣市系統確認。
