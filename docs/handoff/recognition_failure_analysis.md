### 門檻與紀錄的限制

現行 OCRModel 的預設 min_width=58、max_distance=22。PlateOCRTracker 雖有「遠離時放寬到 45 px」，但需要先有成功建立的 rec 與 last_plate_w。
因此從未達到 58 px、也沒有既有有效辨識的車牌，不能靠該分支獲得第一次 OCR。除上表外，漏報影片也有同類現象：

| 影片／目標 ID | 牌框筆數 | 最大寬度 | OCR 嘗試來源 |
| --- | ---: | ---: | --- |
| ms06／000003 | 51 | 39.2 px | 無 |
| s05／000004 | 3 | 54.3 px | 無 |
| cdy06／000012 | 151 | 56.7 px | 無 |
| soc03／000001 | 35 | 55.9 px | 無 |

這些尺寸足以解釋當前門檻拒絕；距離、held、取樣間隔也可能同時影響。
現有 plates.raw_text 是 get_plate_raw 回傳的「快取最佳原文」，不是本幀 OCR 原始結果；text 可能來自投票，text_confidence 則可能仍來自最佳原文。
ocr_source_frame 記最近一次嘗試，不能還原每次被拒絕的原文、分數或原因；不能把同一文字出現 100 幀當成 100 次獨立辨識支持。
目前能確認錯誤的最終輸出，尚不能完整量化「OCR 模型」與「投票／過濾」各自造成多少錯誤。

ctm02／ctm04 的正確後續文字，是已存在於輸出的回溯證據。若補回策略可靠，這兩筆可能改善；**尚未實作，不能宣稱車牌已從 6/15 提升到 8/15**。
補回應保留事件原時間與原證據，另外記錄 plate_observed_at／來源幀；禁止把較晚才看見的車牌偽裝成事件當下的讀數，也不能跨不確定的 ID 自動轉移。

### 雙線診斷的誤導點

unsupported_footprint_or_invalid_box 把不同原因合在一起。本次對上述 7 個雙黃線漏報、已指定目標 ID 的 222 筆此類診斷逐筆核對，車框均為有限數值且寬高有效。
由 double_lines.vehicle_line_position 的 return None 分支可判斷，這些是車底三個參考點無法在可用線段內取得足夠端點支援，**不是 222 個壞車框**。
建議後續拆成 invalid_bbox、outside_line_support、endpoint_margin 等診斷，附線段端點、外插限制與失敗參考點；先定位，不直接放寬外插距離。

## 四、建議下一步與接手 prompt

優先順序依本次實際證據調整：

1. **先補可觀測性**：OCR 每次嘗試的原文、分數、裁切尺寸與拒絕原因；雙線的分支原因；區域狀態的清除理由與已累積秒數。預設關閉，確認不改事件結果。
2. **評估同追蹤的後續車牌補充**：先做離線對照，以 ctm02／ctm04 為正例；以換 ID、錯牌鎖定、同時多車為反例。需明列輸出欄位及消費端，保留原事件證據，不直接覆寫歷史證據。
3. **針對幾何與燈號逐類修正**：cdy03／cdy06 優先看線段支援；cdy05／cdy07／ms07 看運動失效；soc03 看短暫重疊消失；s05／ms06 看燈號辨識與時序。一次只改一類，記錄新增誤報。
4. 小牌 OCR 的低寬度試讀獨立評估，不能全域降低門檻，也不將所有漏報當 OCR 問題。動態取樣暫留診斷階段。
